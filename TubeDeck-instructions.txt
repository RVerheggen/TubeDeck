Let's build the first version as a real Windows desktop application, not just a visual prototype.

I'll call it TubeDeck and use React, TypeScript, Tauri 2, Rust, yt-dlp and FFmpeg.

The first implementation will include:

- Working download queue with multiple simultaneous downloads.
- URL input for individual videos and playlists.
- Video, audio, codec and quality settings.
- Advanced yt-dlp configuration.
- Live command preview with copy functionality.
- Download progress, speed and ETA.
- Saved presets.
- Dark and light themes.
- Download history and diagnostic logs.
- Windows installation and build instructions.

I'll use custom CSS illustrations and icons, so the interface doesn't depend on downloading external design assets.

One distinction: I can provide the complete copyable project source here, but cannot attach a verified ZIP file in this session.

## 5. Rust download engine — `src-tauri/src/lib.rs`

This is the native backend that launches yt-dlp without using a shell. It handles arguments separately, which is safer than constructing a PowerShell command.

rust

```rust

use serde::Deserialize;
use std::process::Command;
use std::sync::{Arc, OnceLock};
use tauri::Emitter;
use tokio::sync::Semaphore;

static DOWNLOAD_LIMIT: OnceLock<Arc<Semaphore>> = OnceLock::new();

#[derive(Deserialize, Clone)]
#[serde(rename_all = "camelCase")]
struct DownloadOptions {
    quality: String,
    format: String,
    audio: String,
    fragments: u32,
    retries: u32,
    thumbnail: bool,
    metadata: bool,
    chapters: bool,
    subtitles: bool,
    folder: String,
    parallel: Option<usize>,
}

#[tauri::command]
async fn enqueue_download(
    app: tauri::AppHandle,
    id: String,
    url: String,
    options: DownloadOptions,
) -> Result<String, String> {
    if url.trim().is_empty() {
        return Err("URL cannot be empty".into());
    }

    if !(url.starts_with("https://") || url.starts_with("http://")) {
        return Err("Only HTTP and HTTPS URLs are supported".into());
    }

    let limit = options.parallel.unwrap_or(3).clamp(1, 10);
    let semaphore = DOWNLOAD_LIMIT.get_or_init(|| {
        Arc::new(Semaphore::new(limit))
    }).clone();

    let permit = semaphore.acquire_owned()
        .await
        .map_err(|e| e.to_string())?;

    let app_handle = app.clone();
    let job_id = id.clone();

    tokio::task::spawn_blocking(move || {
        let _permit = permit;

        let result = run_download(&url, &options);

        match result {
            Ok(output) => {
                let _ = app_handle.emit(
                    "download-finished",
                    serde_json::json!({
                        "id": job_id,
                        "output": output
                    })
                );
            }
            Err(error) => {
                let _ = app_handle.emit(
                    "download-error",
                    serde_json::json!({
                        "id": job_id,
                        "error": error
                    })
                );
            }
        }
    });

    Ok(id)
}

fn run_download(
    url: &str,
    options: &DownloadOptions
) -> Result<String, String> {
    let mut cmd = Command::new("yt-dlp");

    cmd.arg("--newline")
       .arg("--progress")
       .arg("--no-warnings")
       .arg("--concurrent-fragments")
       .arg(options.fragments.to_string())
       .arg("--retries")
       .arg(options.retries.to_string());

    if options.audio != "best" {
        cmd.arg("-x")
           .arg("--audio-format")
           .arg(&options.audio)
           .arg("--audio-quality")
           .arg("0");
    } else {
        let format = format!(
            "bv*[height<={}]+ba/b",
            options.quality
        );

        if options.quality == "best" {
            cmd.arg("-f").arg("bestvideo*+bestaudio/best");
        } else {
            cmd.arg("-f").arg(format);
        }

        cmd.arg("--merge-output-format")
            .arg(&options.format);
    }

    if options.thumbnail {
        cmd.arg("--embed-thumbnail");
    }

    if options.metadata {
        cmd.arg("--embed-metadata");
    }

    if options.chapters {
        cmd.arg("--embed-chapters");
    }

    if options.subtitles {
        cmd.arg("--write-subs")
           .arg("--write-auto-subs");
    }

    let output_template = format!(
        "{}/%(title)s.%(ext)s",
        options.folder.trim_end_matches(['/', '\\'])
    );

    cmd.arg("-o")
        .arg(output_template)
        .arg(url);

    let output = cmd.output()
        .map_err(|e| format!(
            "Could not launch yt-dlp. Is it installed and on PATH? {e}"
        ))?;

    if output.status.success() {
        Ok(String::from_utf8_lossy(&output.stdout).to_string())
    } else {
        Err(String::from_utf8_lossy(&output.stderr).to_string())
    }
}

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .invoke_handler(tauri::generate_handler![
            enqueue_download
        ])
        .run(tauri::generate_context!())
        .expect("Error while running TubeDeck");
}
```

Add the `parallel` value to the options object in `App.tsx`:

tsx

```tsx
parallel
```

The backend uses a semaphore to limit simultaneous jobs. For the first implementation, this limit is initialized when the first job is submitted; changing the limit later requires restarting the engine.

Important implementation note: the backend currently waits for each yt-dlp process to finish and emits completion/error events. The next integration step is to subscribe to those events in React and parse progress output so the illustrative progress cards become live. The frontend's initial sample cards are demonstration data, not real downloads.

## 10. What remains before calling it production-ready

I want to be transparent about the current source: it is a substantial starter implementation, not yet a finished, tested application.

These are the next engineering tasks:

| Feature | Current state |
| --- | --- |
| Main UI and styling | Implemented |
| Command generation | Implemented for basic options |
| Copy command | Implemented |
| Preset selection | Basic examples |
| Native yt-dlp launching | Implemented |
| Concurrent job limiting | Basic backend semaphore |
| Live progress updates | Needs integration |
| Pause/resume individual jobs | Needs implementation |
| Persistent queue and history | Needs SQLite |
| Playlist item selection | Needs implementation |
| Custom argument editor | Needs implementation |
| Automatic yt-dlp updates | Needs implementation |
| Installer testing | Needs Windows build testing |

One important technical improvement before relying on it: the backend should use streaming process output rather than `Command::output()`, allowing it to update download progress continuously. It should also persist jobs and support cancellation and graceful shutdown.
